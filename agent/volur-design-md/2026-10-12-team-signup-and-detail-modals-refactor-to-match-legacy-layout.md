# 竞赛报名表与战队详情弹窗对比分析与排版重构记录

## 1. 变更背景与需求分析
在新一代前端工程（`src/volur-lite-view-NEXT`）中，原有的竞赛报名与队伍管理组件被拆分为 `TeamSignupModal.vue`（创建报名）和 `TeamDetailModal.vue`（队伍查看）。然而相比经典前端（`src/volur-lite-view`）中经过高度打磨的 `TeamFormModal.vue`，存在显著的排版退化、字段缺失以及校验漏洞：
1. **排版布局退化**：新前端原 `TeamSignupModal` 采用单列垂直卡片堆叠，队员以卡片为单位垂直延展，空间利用率极低；丢失了旧前端经典的顶部双栏黄金分割（左侧队伍基础资料，右侧竞赛报名要求与管理员特别说明看板）以及中间高密度横向全息表格；
2. **核心业务字段缺失**：新前端原 `TeamSignupModal` 遗漏了 `employeeNumber`（学号/工号）、`department`（学院/部门）、`position`（班级/职位）以及根据单位类型（`SCHOOL` vs `ENTERPRISE`）动态切换表头文案的关键逻辑；
3. **输入体验缺失自动预填**：旧前端打开时能通过用户 Profile 接口自动预填首行队长信息，而新前端此前为全空白手动输入；
4. **防御性校验薄弱**：新前端缺少中国四大电信运营商合法号段校验（`isValidChinaPhone`）、GB 11643-1999 二代身份证 18 位加权校验码核验（`isValidIdCard`）以及队内学号/手机/邮箱/身份证查重。

本次重构旨在完整复刻旧前端紧凑、高效的赛制级排版布局与严谨数据流，同时严格继承并应用新前端 Google Material Design 3 的色彩与表面阶梯规范。

## 2. 核心对比差异剖析

| 维度 | 经典前端 (`TeamFormModal.vue`) | 新前端原实现 (`TeamSignupModal` + `TeamDetailModal`) | 新前端重构后设计 (`TeamSignupModal` + `TeamDetailModal`) |
| :--- | :--- | :--- | :--- |
| **组件形态** | 单组件三模统一（`create` / `view` / `edit`） | 拆分为两个独立的展示/创建组件 | 保持业务视图调用接口兼容，双组件全息升级 |
| **顶部 Meta 布局** | 双栏 `1fr 1px 1fr`：左侧基础表单，右侧报名须知看板 | 单栏大卡片平铺，无竞赛须知与特别说明 | 双栏响应式网格：左侧基础信息，右侧竞赛时间/人数/领队/特别说明看板 |
| **成员输入形式** | 横向滚动 `n-table`，单元格内嵌输入控件，第 0 行队长保护 | 纵向大卡片列表堆叠（Card Stack），垂直高度过长 | 横向滚动 `n-table`（`min-w-[1240px]`），紧凑高效，第 0 行队长保护 |
| **字段完整度** | 包含真实姓名、性别、角色、学号/工号、手机、邮箱、身份证、学院/部门、班级/职位 | 缺失学号/工号、学院/部门、班级/职位 | 100% 完整覆盖全部字段，支持单位类型智能切换表头 |
| **领队配置区** | 折叠文字链接触发，独立表格录入 | 独立卡片常驻或平铺 | 折叠文字链接触发，独立规范表格，支持选填/必填区分 |
| **队长数据预填** | 自动拉取当前登录用户 Profile 预填队长行 | 无自动预填，需手动重输 | 自动拉取 `getCurrentUserProfileApi()` 预填姓名、性别、手机、邮箱、学院 |
| **身份与格式校验** | 严格校验四大运营商号段、二代身份证校验码、队内排重 | 仅有基础 trim 判空，无格式核验与查重 | 完整移植 `validation.ts`，严谨执行手机号段、身份证 ISO 7064 核验与全局防重 |
| **视觉与色彩规范** | 经典模式（纯黑 `#000000` 主按钮，`#444444` 文字） | Google 风格初版，但排版松散 | 严格对齐 Google Material 3：Google Blue `#1a73e8`/`#a8c7fa`，Google Gray，支持深色模式 |

## 3. 具体改动清单

1. **新增身份与号段校验工具库** (`src/volur-lite-view-NEXT/src/utils/validation.ts`)：
   - 提取并实现纯净版中国四大电信运营商合法号段识别与校验（`isValidChinaPhone`）；
   - 提取并实现 GB 11643-1999 二代居民身份证 18 位加权模 11 校验码算法（`isValidIdCard`）；
   - 提取身份证生日与性别解析工具；
   - 严格遵循纯粹代码与零注释铁律。

2. **重构战队报名弹窗** (`src/volur-lite-view-NEXT/src/views/competition/components/TeamSignupModal.vue`)：
   - 容器尺寸统一为 `w-[1040px] max-w-[96vw] rounded-2xl`，支持浅色 `#ffffff` 与暗色 `bg-google-surface-darkCard`；
   - 顶部布局重构为 `grid-cols-1 lg:grid-cols-[1fr_1px_1fr]` 双栏分栏，左侧队伍名称、所属单位、单位类型、队伍简介，右侧展示竞赛报名时间、比赛时间、人数限制、领队限制与管理员特别说明；
   - 参赛成员重构为 `n-table` 紧凑表格，表头动态切换（学校单位显示“学号/学院/班级”，企业单位显示“工号/部门/职位”）；
   - 实现打开弹窗时自动读取当前用户 Profile 预填队长数据；
   - 领队/指导老师名册采用文本链接按需折叠；
   - 主按钮采用 Google Blue 药丸按钮，保留新前端视觉规范。

3. **重构战队详情弹窗** (`src/volur-lite-view-NEXT/src/views/competition/components/TeamDetailModal.vue`)：
   - 弹窗尺寸与布局对齐 `w-[1040px] max-w-[96vw]`；
   - 顶部展示战队名称、所属单位、单位类型、队伍简介、审核状态 Tag、我的角色 Tag；
   - 成员与领队列表升级为完整宽表展示，完整补齐学号/工号、联系方式、脱敏身份证（前6后4）、学院/部门、班级/职位；
   - 保留队长解散战队、重新邀请、移除成员等核心管理动作。
