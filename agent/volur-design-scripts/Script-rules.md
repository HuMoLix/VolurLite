# Volur Lite 自动化脚本编写规范 (Script-rules.md)

本文档定义了 Agent 在本项目中编写与使用辅助脚本（Python / C / Go / Shell 等）的强制性约束准则。

---

## 1. 核心定位与适用边界 (Applicability & Purpose)

1. **仅限大批量重复性任务 (Batch Operations Only)**：
   - 脚本**仅在需要 Agent 进行跨多文件的大批量、高重复性作业**（如全量代码合规扫描、大规模模式匹配与替换、AST 批量审查、批量文件重命名/迁移等）时使用。
   - **严禁针对性任务滥用**：对于定位明确的单文件、少数几个文件的针对性修改或调试任务，严禁随意创建脚本，应直接使用内置文件编辑工具。
2. **纯 Agent 内部工具 (Agent-Only Consumption)**：
   - 脚本专供 Agent 自身调用和解析，非面向终端用户的交付软件。

---

## 2. Token 零浪费与极简代码准则 (Token Optimization & Zero Bloat)

1. **杜绝冗余注释与文档**：
   - 严禁编写长篇 docstring、类与函数冗余注释、说明性占位符；
   - 代码以精简、直接、直击需求核心为唯一目标，不浪费任何多余 Token。
2. **去除装饰性 UI 与无用打印**：
   - 严禁输出 ASCII 分割线（如 `=======`）、欢迎语、花哨的统计面板等无关文本；
   - 严禁编写复杂的交互式命令行帮助信息。

---

## 3. 输出与返回结果规范 (Output Design)

1. **精准输出核心数据**：
   - 脚本标准输出（stdout）仅返回 Agent 决策与操作所需的最小必要信息（如问题文件路径、行号、违规项、或紧凑的 JSON / 纯文本列表）；
   - 无异常或全部符合预期时直接静默退出（或仅输出单行确认），不产生冗长噪声。
2. **错误处理极简**：
   - 遇到异常快速失败并输出关键报错原因即可，无需包装多层冗长的错误拦截日志。

---

## 4. 存储与命名规范 (Storage & Location)

- 所有脚本必须统一存放在项目根目录下的 `volur-design-scripts/` 文件夹中；
- 脚本命名简短明了（如 `scan_controllers.py`, `replace_keys.py`），严禁在项目源码目录平铺临时脚本。
